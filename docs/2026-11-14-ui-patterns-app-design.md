# さわれるUI図鑑 設計書（仮称）

作成日：2026-11-14 ／ 状態：設計（実装前）

## 1. このアプリで何をしたいか

自分が作るアプリやサイトの出来を上げるために、よく見るUIの動きを、実際に触りながら名前と使いどころごと覚えるWebアプリを作る。

きっかけは2本のTikTok動画（usutaku4 の投稿）だった。どちらも「全部見たことはあるのに名前を知らない。名前さえ言えればAIが一発で作ってくれる」という内容で、合わせて13個の動きが紹介されていた。

| 動画 | 紹介された動き |
|---|---|
| 1本目（Webサイト向け） | ハンバーガーメニュー、パンくずリスト、カルーセル、モーダル、アコーディオン、ラジオボタン、プルダウンメニュー |
| 2本目（スマホアプリ向け） | プルトゥリフレッシュ、スケルトンスクリーン、トースト、ボトムシート、スワイプアクション、オートコンプリート |

利用者はユーザー本人ひとりで、iPhoneとMacの両方で遊ぶ。本人はiOS（SwiftUI）、Windows向けデスクトップ（Electron）、Chrome拡張、Webのアプリを、AIに頼みながら作っている。

名前を覚えるのは手段で、目的はその先にある。名前と一緒に「どう作ると丁寧か」まで知っていれば、AIへの頼み方が具体的になり、できあがるアプリの出来が上がる。

## 2. 目標と、やらないこと

### 目標

- 動き1つにつき、触る・名前を知る・使いどころを知る・丁寧な作りとの違いを確かめる・AIへの頼み方を持ち帰る、までを1画面で済ませられる
- 遊びながら名前を覚えられる仕組みがある（クイズ、覚えた印）
- iPhoneのSafariでもMacのブラウザでも、同じ手ざわりで動く

### やらないこと

- iOSネイティブ版（SwiftUI）は作らない。使ってみて物足りなければ後で検討する
- ログインや複数人での利用、学習記録のサーバー保存はしない
- 部品集やライブラリとして他のアプリに組み込める形にはしない。見本のコードは「読んで分かる」ことを優先する

### 失敗とみなすもの

次のどれかに当たれば、動いていても失敗とする。

- 読み物になっていて、触って確かめられない動きがある
- 名前の暗記テストだけで終わり、作るときの判断（向き不向き、丁寧な作り）につながらない
- 名前が独自の呼び方になっていて、AIや検索で通じない
- iPhoneで、Safari自体の動き（下に引くと更新、端から引くと戻る）とぶつかって操作できない

## 3. 作り方の選択肢と決めたこと

| 案 | 内容 | 長所 | 短所 |
|---|---|---|---|
| **A. Webアプリ（採用）** | ブラウザで動くページ | iPhoneとMacで同じものが動く。本人が作るものの大半（Electron、Chrome拡張、Web）が同じWeb技術なので、覚えた動きをそのまま持ち込める | iPhone純正アプリ特有の手ざわりは、似せても本物にはならない |
| B. ネイティブアプリ（SwiftUI） | iPhone・Mac用のアプリ | iOSの動きを本物で触れる。見本をiOSアプリに流用できる | Web特有の動き（マウスを乗せると出る説明など）が不自然。手間がAの2〜3倍かかり、Mac版の使い心地が落ちる |
| C. 両方 | AとBを作る | 理想に近い | 同じ中身を2回作ることになり、最初の一手には重い |

本人がAを選んだ。iOSについては、各カードの「AIへの頼み方」にSwiftUIで頼むときの言い方を添えて補う。

## 4. 1枚のカードに載せるもの

アプリの単位は「動き1つ＝カード1枚」とする。カードには次の6つを載せる。

1. **触れる見本**：画面の枠の中で実際に操作できる。枠は「スマホ」と「PCのブラウザ」の2種類を用意し、カードごとに、その動きが主に使われる側を最初に表示する（ボトムシートやスワイプアクションはスマホ、パンくずリストやツールチップはPC）。両方で使う動きは枠を切り替えて見比べられる。「丁寧な作り」の基準は枠に合わせ、スマホ枠では Apple のヒューマンインターフェイスガイドライン、PC枠では Web で広く使われている作法（WAI-ARIA の作り方の手引きなど）に沿う【Claudeの判断】
2. **名前**：日本語名と英語名、別名。英語名はAIへの指示や検索で通じやすい。別名の例として、プルダウンメニューは英語では dropdown や select と呼ぶことが多い。
3. **ひとことで言うと**：何をする動きかを1〜2文で書く。
4. **向いている場面・向かない場面**：例として、モーダルは削除前の確認に向くが、長い入力フォームには向かない。向かないときの代わりも書く（長い入力なら別ページにする）。
5. **雑な作りと丁寧な作りの比較**：見本の上にある切り替えスイッチで、同じ動きを「雑」と「丁寧」で切り替えて触れる。丁寧側の工夫を「こだわりポイント」として2〜4個、短く説明する。
6. **AIへの頼み方**：コピーボタン付きの例文を3段階で載せる。
   - 一言版：「設定画面にトーストを出して」
   - こだわり版：こだわりポイントを入れたもの。「保存したら画面下にトーストを出して。3秒で消して、マウスを乗せている間は消さない。続けて出たら重ねずに入れ替える」
   - SwiftUI版：iOSアプリで頼むときの言い方

このアプリの価値がいちばん出るのは5の比較なので、ここに最も手間をかける。例を3つ挙げる。

| 動き | 雑な作り | 丁寧な作り（こだわりポイント） |
|---|---|---|
| トースト | 1秒で消えて読めない。ボタンの上に重なる。連続で出すと積み重なる | 3〜5秒表示。マウスを乗せている間は止まる。押せるボタンを隠さない位置に出る。画面読み上げにも伝わる |
| モーダル | Escキーでも外側のタップでも閉じない。後ろの画面がスクロールしてしまう | Esc・外側タップ・閉じるボタンで閉じる。開いている間は後ろが動かない。キーボード操作がモーダルの中に留まる |
| プルトゥリフレッシュ | 少し触れただけで更新が始まる。更新中か終わったかが分からない | 一定距離まで引くと「離すと更新」に変わる。更新中はくるくる回り、終わると「更新しました」と出る |

## 5. 遊び方

画面は3つのモードに分ける。

### 図鑑モード

カードを分類ごとに一覧で見て、選んで触る。iPhoneでは一覧からカードに進む1列の画面、Macでは左に一覧・右にカードの2列の画面にする。

```
[Mac]
┌─────────────┬──────────────────────────────┐
│ ナビゲーション │  トースト  Toast             │
│  ハンバーガー  │  ┌────────┐  雑 ○─● 丁寧     │
│  パンくず      │  │ スマホ枠 │  こだわりポイント│
│ 待ち・お知らせ │  │ (見本)  │  ・3〜5秒表示    │
│ ▶トースト     │  └────────┘  ・重ねない       │
│  スケルトン    │  向いている／向かない          │
│  ...          │  AIへの頼み方 [コピー]         │
└─────────────┴──────────────────────────────┘
```

### 名前当てクイズ

見本が1つ出て、触ってから4択で名前を当てる。正解すると、そのカードに「名前を言えた」の印が付く。間違えたら、選んだ名前の動きと見比べられるようにする（例：トーストとスナックバーの違い）。

### 逆引き（こんなときどれ？）

「保存できたことを、作業の邪魔をせずに伝えたい」のような場面が出て、合う動きを選ぶ。答えでは、選ばなかった候補がなぜ合わないかも短く説明する。作るときの判断力を鍛えるためのモードである。

### 覚えた印

カードごとに「触った」「名前を言えた」「逆引きで当てた」の3つを記録し、一覧で進み具合が分かるようにする。記録はブラウザ内（localStorage）に保存し、消えても遊べるようにする。

## 6. 収録する動き

本人の希望で、動画で紹介されたものに限らず広く収録する。10分類・79個とする。★は動画で紹介された13個、◆は動画にないもののうち、よく使うので段階2で先に作る8個である。

| 分類 | 動き |
|---|---|
| ナビゲーション | ★ハンバーガーメニュー、★パンくずリスト、◆タブ、◆ボトムナビゲーション（タブバー）、ドロワー、ページネーション、無限スクロール、スティッキーヘッダー、目次とスクロール連動 |
| 表示・重ねる | ★カルーセル、★アコーディオン、★モーダル、★ボトムシート、◆ツールチップ、ポップオーバー、カード、バッジ、空っぽ画面（エンプティステート） |
| 入力 | ★ラジオボタン、★プルダウンメニュー、★オートコンプリート、◆チェックボックス、◆トグルスイッチ、セグメンテッドコントロール、スライダー、ステッパー、日付ピッカー、チップ（タグ入力）、検索バー、入力中のエラー表示（インラインバリデーション）、ファイルのドラッグでのアップロード、パスワードの表示切り替え、文字数カウンター、評価の星、色の選択、ワンタイムコードの入力欄、入力の自動区切り（電話番号やカード番号の入力マスク） |
| 一覧・データ | 表の並べ替え、絞り込み（フィルター）、検索語のハイライト、一括選択、行を開いて詳細を見る、列や見出しの固定、画像の拡大表示（ライトボックス）、ギャラリーの段組み（マソンリー） |
| 待ち・お知らせ | ★プルトゥリフレッシュ、★スケルトンスクリーン、★トースト、◆スナックバー（取り消し付き）、スピナー、プログレスバー、◆確認ダイアログ、先に画面だけ更新する作り（楽観的UI）、処理中を示すボタン |
| 指で操作する | ★スワイプアクション、◆ドラッグ＆ドロップでの並び替え、長押しメニュー（コンテキストメニュー）、ピンチで拡大、元に戻す（Undo） |
| 画面の組み方 | 分割画面（左右のペイン）、折りたためるサイドバー、固定フッター、上に戻るボタン、画面幅で並びが変わる作り（レスポンシブ） |
| 操作・便利機能 | コマンドパレット（⌘K で開く検索窓）、キーボードショートカット、コピーボタン、ダークモードの切り替え、共有シート、お気に入りボタン |
| 動き・演出 | 画面の切り替えアニメーション、スクロールに合わせた表示、押したときの反応（波紋など）、触感フィードバック（振動）、スクロールで縮むヘッダー、数字のカウントアップ |

触感フィードバック（振動）は、iPhoneのSafariでは振動させる仕組みが使えない。カードでは、振動の代わりに画面上の表示で示し、ネイティブアプリでどう頼むかを説明する【Claudeの判断】。

名前は、Apple のヒューマンインターフェイスガイドライン、Google の Material Design、Web で広く使われている呼び方のどれかに合わせる。呼び方が分かれるもの（トーストとスナックバーなど）は、カードの別名欄と比較の説明で扱う。

## 7. 技術の決まりごと

- **置き場所**：GitHub Pages で公開する（本人が選んだ）。URLを知っていれば誰でも見られるが、中身に個人情報や機密はない。ほかの候補は、Claude の Artifact（通信なしで使えず、ページに埋め込まれるため引っ張る操作がブラウザとぶつかりやすい）と、Mac mini＋Tailscale（Mac mini が動いている間しか使えない）だった。公開の操作そのものは、実行前に本人に確認する
- **ホーム画面から開く**：iPhoneのホーム画面に追加すると、ブラウザのバーなしの全画面で開くようにする（Web アプリのマニフェストを置く）。通信なしで動かすために Service Worker でファイルを保存しておく。ブラウザで開いたときと、ホーム画面から開いたときの両方で、見本の操作がブラウザの更新や戻る操作とぶつからないことを確かめる
- **作り**：HTML・CSS・JavaScript だけで作り、外部のライブラリやビルドの仕組みは使わない。見本のコードを本人が読んで分かることを優先するためである【Claudeの判断】
- **データ**：カードの文章（名前、説明、向き不向き、こだわりポイント、頼み方）は、見本のコードとは別のデータファイルにまとめる。動きを足すときに、データ1件と見本1つを追加すれば済むようにする
- **見本**：動き1つにつき1ファイルとし、「雑」と「丁寧」の両方を同じファイルに持たせる
- **端末**：iPhoneのSafari、MacのSafariとChromeで動作を確かめる。タッチとマウスの両方で操作でき、指の動き（引く、スワイプ、長押し、ピンチ）はマウスのドラッグでも再現する
- **Safariとの衝突**：見本の枠の中では、ページ全体のスクロールや更新、戻る操作が起きないようにする
- **動きを減らす設定**：OSで「視差効果を減らす」を選んでいる場合は、アニメーションを控えめにする
- **通信**：最初に開いたあとは通信なしで動く。外部サービスへの送信や計測は入れない
- **言語**：画面は日本語。英語名は各カードに併記する

## 8. 作る順番

| 段階 | 内容 | できたと言える条件 |
|---|---|---|
| 1 | 画面の骨組み（図鑑モード、スマホ枠とPC枠の切り替え、雑・丁寧の切り替え、頼み方のコピー）と、トースト・モーダル・プルトゥリフレッシュの3つ | iPhoneとMacの両方で3つを触れ、切り替えで違いが分かり、頼み方をコピーできる |
| 2 | 動画で紹介された残りの10個（★）と、動画にないよく使う8個（◆）、名前当てクイズ、覚えた印 | ★と◆の21個すべてが段階1と同じ形で揃い、クイズで遊べる |
| 3 | 残りの58個と、逆引きモード | 第6節の一覧がすべて揃う |

段階3は量が多いので、分類ごとに区切って作り、区切りごとに動作を確かめる。

段階1が終わった時点で一度本人に触ってもらい、カードの作りや切り替えの見せ方を見直してから段階2に進む。

## 9. まだ決めていないこと

- **アプリの正式名**：「さわれるUI図鑑」は仮の名前
- **PlexusUI との関係**：法人共通の部品集 PlexusUI（`~/Developer/plexus-ui`、`~/Developer/_shared/PlexusUI`）にすでにある部品と、このアプリのカードを結びつけるか。段階3のあとで検討する

## 10. 作る人に任せること

- 見本ごとの細かい数値（アニメーションの時間、引く距離など）。第4節の「丁寧な作り」の考え方に沿って決める
- 79個それぞれの、こだわりポイントと向き不向きの文面。名前と同じく、公式のガイドラインと食い違わないようにする
- 画面の色や文字の大きさ。それ自体が「丁寧な作り」の見本になるよう、読みやすさを優先する
